# 草稿重新打开与本地搜索

本文说明两件事：**本地草稿**（自动保存 → 在 草稿 文件夹里出现 → 双击/Enter/“继续编辑”重新打开）和 **本地搜索**（防抖、范围切换、查询语法、FTS5 / 三元组 / LIKE 路由、高亮）。数据库迁移为 **V3**（`drafts` 表 + `messages_trgm` 三元组 FTS 表）。

> 截图（演示数据、免安装版、未登录任何真实账号）在 `shots/`：`20-drafts-folder.png`、`20b-drafts-reading-pane.png`、`21-compose-from-draft.png`、`22-search-cn-highlight.png`、`22b-search-cn-reading-highlight.png`、`23-search-operators.png`、`24-search-empty.png`。

## 1. 草稿

### 1.1 保存

- 撰写窗口每 3 秒（内容有改动时）自动保存一次到本地 `drafts` 表；窗口关闭时再保存一次。全部字段都会保存：发件账号、收件人 / 抄送 / 密送、主题、正文、附件、回复上下文（`In-Reply-To` / `References` / 被引用的原文 HTML 与纯文本）。
- **附件**在第一次保存时复制到应用自己的目录 `drafts\{草稿 Id}\`（与数据库 / 设置文件同一目录；用 `MAILCLIENT_DB` 时跟着数据库走）。之后原文件被移动、改名或删除都不影响草稿。重新保存会清理已被移除的附件副本；草稿被删除（发送 / 丢弃 / 列表删除）时整个目录一并删除；启动时清理没有对应草稿的孤儿目录。
- 草稿也写入该账号“草稿”文件夹的 `messages` 表（`Id = draft:{草稿Id}`），因此同样进入搜索索引、计数和列表排序。正文与主题都为空的草稿会被删除而不是保存。
- 账号没有“草稿”文件夹时（尚未同步出来）自动保存会安静跳过——**已知缺口**。

### 1.2 列表

- 每个账号的“草稿”文件夹，以及左侧“收藏夹”里的统一“草稿”，都把**本地草稿**和**服务器同步下来的草稿**合并显示，按最后编辑时间倒序；本地草稿带“本地草稿”徽标。
- 服务器草稿一旦被打开并生成了本地副本，原服务器条目在列表里隐藏（避免重复），文件夹计数也不重复计算。
- 列表中本地草稿的 已读 / 标记 / 归档 操作无效（不会排入服务器回写队列）。

### 1.3 重新打开

- 入口：双击、选中后按 Enter、阅读窗格里的“继续编辑”按钮。
- 重新打开会还原：账号、To/Cc/Bcc、主题、正文、附件（缺失的文件会被跳过）、回复上下文；之后发送出去的邮件仍带正确的 `In-Reply-To` / `References` 与引用原文。
- **同一份草稿不会开两个窗口**：再次打开会激活已有窗口（窗口键 `draft:{草稿Id}`；从服务器草稿打开用 `src:{邮件Id}`，保存出本地副本后切换为 `draft:`）。并发打开也只会得到一个窗口。
- 服务器草稿重新打开时会走与普通邮件相同的正文懒加载（打开时拉取完整正文与附件列表）；若服务器草稿没有可用 RemoteUid / Graph Id，仍可能只有预览——**边缘缺口**。

### 1.4 发送 / 丢弃 / 关闭 / 删除

| 操作 | 行为 |
| --- | --- |
| 发送 | 入发件箱成功后删除本地草稿（含附件副本），若来源是服务器草稿则排入一条服务器 Delete |
| 丢弃 | 弹出确认；确认后删除草稿并关闭窗口 |
| 关闭窗口 | 保留草稿（下次在草稿文件夹继续） |
| 列表删除（右键菜单 / Delete 键 / 阅读窗格“删除”） | 确认后删除草稿，若有打开的窗口则先 `Abandon` 再关闭，不会被自动保存复活 |

### 1.5 服务器草稿同步

- **只读方向**已有：服务器上的草稿随同步进入列表。
- **回写方向（IMAP `APPEND` 到 Drafts 并带 `\Draft` 标志、按 Message-ID 替换旧版本；Graph 创建 / 更新 draft message）本次未实现**，作为已知缺口。草稿目前只保存在本机；发送或删除已有服务器副本的草稿时，会排入服务器 Delete，从而不会在服务器上留下旧副本。

## 2. 本地搜索

### 2.1 界面

- 中栏顶部搜索框（`Ctrl+F` 聚焦），输入后 **250 ms 防抖**再查；右侧下拉切换范围：**当前文件夹 / 当前账号 / 全部邮箱**。
- “当前账号 / 全部邮箱”会排除垃圾邮件和已删除邮件；“当前文件夹”就是你正在看的那个文件夹（含统一视图，如“所有收件箱”）。
- `Esc` 清空搜索并恢复列表；`Enter` 提交（同时记入“最近搜索”，最多 10 条，保存在设置里）；聚焦空搜索框会显示最近搜索建议。
- 没有结果显示“没有找到邮件”；标题下方显示“找到 N 封 · 范围”。
- 命中词在列表行的**主题 / 发件人 / 预览**中以黄色高亮；在阅读窗格的纯文本正文中同样高亮，HTML 正文只在文本节点内高亮（不会改坏标签、`<style>`、`<script>`、实体）。

### 2.2 查询语法

多个条件之间是 **AND**。

| 写法 | 含义 |
| --- | --- |
| `词语` | 在 主题 / 发件人 / 预览 / 正文 中匹配 |
| `"精确短语"` | 引号内整体匹配（可含空格） |
| `from:linda` | 发件人（名字或地址）包含 |
| `to:zhang.wei` | 收件人（To/Cc/Bcc 名字或地址）包含 |
| `subject:评审` | 仅主题 |
| `has:attachment` | 有附件 |
| `is:unread` / `is:read` | 未读 / 已读 |
| `is:flagged` / `is:unflagged` | 已标记 / 未标记 |
| `after:2026-09-01` / `before:2026-10-15` | 按日期（`YYYY-MM-DD`，按**本地时区**的当天 0 点换算，`after` 含当天、`before` 不含当天） |

- 操作符名不区分大小写，支持全角冒号；也接受少量中文别名。
- 未知操作符、取值不合法（如 `before:abc`、`has:foo`）、取值为空的操作符，**按普通文字**处理，不会报错。
- 例：`from:linda has:attachment`、`合同 after:2026-09-01 is:unread`、`"数据迁移方案" subject:评审`。

### 2.3 索引与路由

SQLite 版本 3.41.2（`e_sqlite3`），支持 `tokenize='trigram'`，迁移时用 try/catch 探测，不支持时自动退回旧路径。有三条路径，由 `SearchRouter` 对**每个词**单独选择：

| 词的类型 | 路径 | 说明 |
| --- | --- | --- |
| ≥ 3 个字符（按码点，中英文都一样） | `messages_trgm`（FTS5 trigram） | 中文子串、拉丁子串都能命中（“合同修”能命中“合同修改稿”） |
| 1–2 个英文字母 / 数字 | `messages_fts`（unicode61）**词前缀** | 注意语义：`re` 匹配以 re 开头的单词，不是任意子串 |
| 1–2 个汉字、含标点 / 非单词字符的短文本 | `LIKE`（转义 `% _ \`） | 全表扫描，见下方性能 |
| `to:` | 始终 `LIKE` 子查询（`recipients` 表） | |

- 索引由触发器 / 写入路径保证随邮件更新而更新（更新、删除、草稿保存都会同步）。
- 搜索字符串里的 FTS 特殊字符（引号、`*`、`-`、括号等）会被转义为字面量，不会抛异常。
- FTS 列过滤（`from:` / `subject:`）用 `{列} : "词"`，各条件 AND 连接。

### 2.4 搜索范围与已知限制

- **只搜本机已同步的数据**。列表同步仍只保证预览；打开邮件后缓存的正文会进入 `messages` 表，但 FTS 触发器是否立即覆盖取决于实现——**未打开过的正文仍不可搜索**，只能命中 主题 / 发件人 / 收件人 / 预览；本地草稿、演示数据与已打开缓存的邮件可搜到正文。
- “在服务器上搜索”（IMAP `SEARCH` / Graph `$search`）**未实现**，作为已知缺口。
- 搜索结果上限由列表查询的 `Limit` 决定（界面默认 200 条）。

### 2.5 性能（开发机，Debug，20 000 封中英混合邮件，4 个文件夹）

测试：`SearchPerformanceTests`（预热一次后取 5 次中位数；结果上限 200 条；断言每项 < 1500 ms）。灌库 20 000 封约 7–11 秒（含 FTS + trigram 两份索引）。

| 查询 | 路径 | 命中 | 中位数 |
| --- | --- | --- | --- |
| `数据迁移方案`（6 字） | trigram | 200+ | 20–27 ms |
| `合同修`（3 字） | trigram | 200+ | 18–24 ms |
| `迁移`（2 字） | LIKE | 200+ | 30–42 ms |
| `迁`（1 字） | LIKE | 200+ | 31–35 ms |
| `invoice` | trigram | 200+ | 17–19 ms |
| `re`（2 字母前缀） | FTS 前缀 | 200+ | 20–23 ms |
| `合同修改稿 invoice`（两词 AND） | trigram | 200+ | 14–16 ms |
| `from:linda` | LIKE | 200+ | 7–8 ms |
| `from:linda has:attachment 报告` | 组合 | 200+ | 9 ms |
| `is:unread is:flagged` | 标志 | 200+ | 17 ms |
| `after:… before:… 合同` | 日期 + trigram | 200+ | 30 ms |
| `subject:评审` | trigram 列过滤 | 200+ | 18 ms |
| 同上 `数据迁移方案`，范围=当前文件夹 / 当前账号 | trigram | 200+ | 4 / 24 ms |
| 稀有 3 字+ 词 / 稀有拉丁词（仅 1 封命中） | trigram | 1 | 0.2–0.3 ms |
| **稀有 2 字 / 1 字汉字（仅 1 封命中，LIKE 最坏情况：扫全表）** | LIKE | 1 | **37–38 ms** |
| 无命中的 8 字中文 | trigram | 0 | 0.2 ms |

即使是最坏的 LIKE 全表扫描，在 2 万封邮件上也不到 40 ms；输入过程中的防抖 + 取消过期查询保证界面不会卡顿。另外测试里把结果与内存中的子串计数逐一核对，保证 trigram / LIKE 路径没有漏结果。

## 4. 快捷键

`Ctrl+F` 聚焦搜索 · `Esc` 清空搜索 · `Enter` 打开选中的草稿（或提交搜索）· `Delete` 删除选中的草稿 / 邮件 · 双击打开草稿。

## 5. 已知缺口

1. 服务器草稿回写（IMAP APPEND `\Draft` / Graph draft message）未实现。
2. 未打开过的邮件正文不可搜索（打开并缓存后取决于 FTS 更新）。
3. 账号没有“草稿”文件夹时自动保存被跳过。
4. 未下载的邮件正文不可搜索；没有“在服务器上搜索”。
5. 1–2 个英文字母按单词前缀匹配，不是任意子串。
