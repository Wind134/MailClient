# 应用内检查更新

「邮件」会向 GitHub Releases 查询是否有新版本，并在你确认后下载安装。

## 仓库地址在哪里改

只在一处：`src/MailClient.Core/Updates/UpdateConfig.cs`

```csharp
public const string Repository = "Wind134/MailClient";   // owner/repo
```

改完重新构建即可（详见 [installer.md](installer.md)）。检查地址、发布页链接都由它派生。

## 检查什么

- 请求公开、无需登录的接口：`GET https://api.github.com/repos/{owner}/{repo}/releases/latest`，带 `User-Agent`，不使用任何令牌。
- 标签形如 `v1.2.3` 或 `v1.2.3.4`，与正在运行的程序版本比较；只有**更新**才算新版本。草稿和预发布版本不会被当成最新版本。
- 启动后约 30 秒检查一次，之后每 6 小时一次；每次请求 20 秒超时。
- 以下情况只写日志（`%LocalAppData%\MailClient\update.log`），不弹窗、不影响使用：离线、超时、仓库还没有任何发布（404）、被限流（403/429）、返回内容无法解析。**手动**点「检查更新」时才会把结果显示在设置页里。

## 设置

「设置 → 常规 → 更新」：

- **自动检查更新**：开关，默认开启。关闭后不会在后台检查，只有手动检查。
- **检查更新**按钮：显示当前版本和结果——「已是最新版本」「发现新版本 x.y.z」或「检查失败」。手动检查会忽略「跳过此版本」。

## 发现新版本时

弹出更新对话框：新版本号和可滚动的更新说明（取自 Release 正文），三个按钮：

| 按钮 | 作用 |
| --- | --- |
| 立即更新 | 见下文，因安装方式而异 |
| 稍后提醒 | 关闭对话框，下一次定时检查（6 小时后）或重启后再次提醒 |
| 跳过此版本 | 记住该版本，自动检查不再为它提醒（之后更高的版本仍会提醒） |

如果主窗口隐藏在托盘，不会强行弹窗：会发一条通知「邮件有新版本 x.y.z」，点击通知（或下次打开主窗口）时显示这个对话框。

## 立即更新（按安装方式）

| 版本 | 做法 |
| --- | --- |
| **exe 安装版** | 在 Release 里找 `MailClient-Setup-*.exe`，下载到 `%TEMP%`（有进度条，可取消）；如果 Release 里有 `SHA256SUMS.txt`，会核对 SHA256，**不一致就拒绝运行并删除下载的文件**；通过后以 `/S /run` 静默运行安装程序（沿用原安装目录；桌面快捷方式不存在时同时传 `/nodesktop`），应用随即退出，安装完成后自动重新启动。账号、邮件数据和设置不受影响。 |
| **MSIX 版** / **绿色版 zip** | 不能原地替换，直接用浏览器打开 Release 页面。 |

下载地址只接受 `https://github.com`（及其 release 资源域名）的链接。

## 发布时需要注意

- Release 必须带 `MailClient-Setup-<版本>.exe`；建议同时带 `SHA256SUMS.txt`（`build-installer.ps1` 会生成，CI 会一并上传，并校验其中条目）。
- Release 正文就是更新说明；CI 用 `docs/release-<版本>*.md` 作为正文。

## 测试用的隐藏开关

环境变量 `MAILCLIENT_UPDATE_FEED`：指向一个本地 JSON 文件或 http(s) 地址（内容同 GitHub 的 `releases/latest` 响应），只用于开发/验证。设置它时才允许从本机回环地址（`127.0.0.1`）下载。普通用户不需要。

## 限制

- 目前没有代码签名，下载的安装程序运行时可能出现 SmartScreen 提示（静默安装通常不弹）。
- 只检查最新的正式发布，不支持回滚和增量更新。
- 仓库为私有时匿名请求会得到 404，不会提示更新。
